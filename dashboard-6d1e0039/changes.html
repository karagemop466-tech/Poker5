Automatic re-check and change log

Every official URL this dashboard depends on is re-fetched on a schedule, hashed, and compared with the previous snapshot. When a page changes, the row is marked and the change is recorded here — you never have to trust that a number is still current.

How a change is detected

  1. The workflow runs scripts/recheck_6d1e0039.py, which downloads each URL with a plain HTTP client (no JavaScript), strips whitespace, and stores a SHA-256 hash in data-6d1e0039/source-hashes.json.
  2. If a hash differs from the previous run, the URL is written to data-6d1e0039/change-log.json with the date, HTTP status and the byte size before and after, and this page marks it changed.
  3. The workflow commits the new hashes, so the next run compares against the most recent state.
  4. A page that returns 403 or 404 is recorded as an error, not as “changed”, so a blocked scraper cannot masquerade as a schedule update.

What the automatic check cannot do

  • It cannot read the Wynn booking engine (JavaScript-only) or the Venetian calendar widget, so hotel totals need the manual re-quote described on the Hotels page.
  • It cannot decide whether a changed page still supports the classification — a change is a prompt to re-read, not a verdict.
