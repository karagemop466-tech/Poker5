Method, standard and formulas

The rules this build applies to every row, so a reader can check a verdict instead of trusting it.

Verification chain

1. Read
the official schedule page and every structure sheet PDF it links; the room's own page for each other venue; the hotel's own resort-fee, parking and terms pages; the county ordinance for the tax.
2. Store
one record per row with the verbatim excerpt of each field, the URL, the retrieval timestamp and the file hash (data/c6087e2c/, data/ea99006a/).
3. Merge
scripts/integrate_bdcaf0bf.py joins the two independent captures, re-reads the sheet text with its own keyword pass, applies the ladder below and keeps every disagreement as data (data/bdcaf0bf/conflicts.json).
4. Build
scripts/build_bdcaf0bf.py refuses to publish a data row without a source link, and refuses a broken internal link.
5. Check
scripts/check_bdcaf0bf.py re-derives every grade from the stored fields, verifies each row's source link, and fails on an inferred value.
6. Re-check
daily, on a GitHub Actions runner: each URL is fetched, hashed and compared; changed rows are badged on the tables and listed on the monitor page.

The single-entry standard

A row is only called single-entry when an official source states a one-entry limit. Rows whose official sheet was read, covers that event number, is one day and contains no re-entry, rebuy, add-on or purchased-stack language are labelled 'sheet read - no re-entry / add-on language': the unverified badge is removed, and the caveat that silence is not a rule stays printed on the row.

Formulas used, exactly

True cost per hotel night
(room rate + mandatory resort fee) × (1 + 0.1338); the fee is inside the tax base because the ordinance defines rent to include separately stated facility and access fees.
Trip cost
entries × listed buy-ins + nights × true hotel cost; parking is added only when the guest opts in, because the official page makes it free for a player with 3 h+ of play.
Estimated end of an event
published start + (level count × level length) + three 15-minute breaks, all from the same sheet; rows without a level count get no estimate.
Value ratio
guarantee ÷ buy-in, computed only when both are published; descriptive, never a forecast.
Overlap test
two events conflict when the later one starts before the earlier one's estimated end, or before its own late-registration window can be reached.
Walk test
verified only where the official page establishes the room is inside the hotel; everything else stays unknown against the 30-minute limit.

What counts as an official source

The property or operator's own page, PDF or ordinance: venetianlasvegas.com, wynnlasvegas.com and cdn.wynnresorts.com, caesars.com, mgmresorts.com property pages, rwlasvegas.com, southpointcasino.com, the WPT's own published PDFs, and clarkcountynv.gov. News sites, forums, odds sites and review sites are never used to set a value. Where a casino publishes a fact only inside an offer's terms, this site says so on the row and keeps the applicability question open (see flags F28 and B04).

  • data/bdcaf0bf/flags.json — the review queue: unverified values, source gaps, cross-session disagreements

  • data/bdcaf0bf/meta.json — counts, the standard, the formulas, the computed trip window and the budget assumption
  • data/bdcaf0bf/plan.json — one primary event plus a conditional fallback per day per room, with the overlap flags

  • data/bdcaf0bf/suggestions.json — the improvement board with options and consequences
  • data/bdcaf0bf/venues.json — each poker room's own page: location, hours, status
  • data/bdcaf0bf/windows.json — every 7-night window scored by how many playable single-entry-standard days it contains
