Suggestions for Improving Decision Making

Review these suggestions and choose the best path before implementing any changes. None are implemented yet.

How to use this page

Each suggestion lists the problem, the proposed change, expected impact, effort, and the decision required. A reviewer should pick which to implement and mark a status. Do not implement anything without reviewing here first.

A. Site improvement suggestions

#SuggestionProblem it solvesExpected impactEffortDecision requiredStatus
S1 Add a live-data feed or scraper that pulls each Strip poker room's official daily schedule each morning. Schedules change daily; static data goes stale fast. High — users always see current tournaments. High Approve data source (official sites only) + scraping cadence. Proposed
S2 Add a "single-entry / freezeout confirmed" toggle filter on the tournaments table. Users can't instantly separate confirmed freezeouts from unverified 1Day events. High — directly supports the "single entry only" rule. Medium Approve filter UI + definition of "confirmed." Proposed
S3 Add live hotel rate lookup (official hotel booking links per date) and auto-calculate true cost/night = rate + resort fee + 13.38% tax. Room rates and true cost/night are blank/unverified today. High — addresses the core hotel-cost question. High Approach each hotel for an official rate API or confirm manual entry process. Proposed
S4 Add walking-distance verification (Google/Apple Maps) from each hotel to the Venetian poker room, with a "≤30 min walk" filter. Walking distances are approximate and unverified. Medium — supports the distance constraint. Medium Verify each route and lock distances. Proposed
S5 Add an 8 AM–all-day feasibility checker that flags when no tournament meets the user's start time. The 8 AM start goal is currently unsupported (earliest ~10:10 AM). Medium — prevents planning around an impossible start. Low–Medium Define the earliest-acceptable start time. Proposed
S6 Add source links + "last verified on" date to every table row. Verifiability is a core requirement; freshness is not tracked. Medium — auditability. Low Adopt "last verified" field as a data standard. Proposed
S7 Add a trip budget calculator (tournament buy-ins × events + hotel true cost × nights + travel/food). No total trip cost exists yet (Q6 unresolved). Medium — total cost of the vacation. Medium Decide calculator inputs and defaults. Proposed
S8 Add a "flag / report outdated info" button on each table row. Users have no way to flag a value that changed. Low–Medium — keeps data honest. Low Route flagged reports to a review queue. Proposed
S9 Add mobile-responsive improvements + a print-friendly "trip sheet" view. Users may want a printed schedule while traveling. Low–Medium Low Approve print stylesheet. Proposed
S10 Add responsible-gaming and 21+ disclaimers more prominently, plus links to official gaming regulators. Current disclaimer is minimal. Low — compliance / user safety. Low Approve disclaimer wording and regulator links. Proposed
